# CPU Manager v0.1.0

> Download links for every release live on the
> [download page](https://open-nexa.github.io/cpum/), which reads them from the
> GitHub releases API. The filenames below are for reference only — do not copy a
> link from this file, it can drift from what was actually published.

The first public release of CPU Manager — a Windows desktop app for inspecting CPU
topology, browsing running processes, and managing their CPU affinity, scheduling
hints and priorities. Vue 3 + Tauri/Rust frontend and backend, plus an optional
Windows service that keeps saved rules applied.

- **Tag:** `v0.1.0`
- **Released:** 2026-09-30
- **Platforms:** Windows x64 / ARM64 (Windows 10 and later)

## Highlights

- **CPU topology inspection** — logical processors, physical cores, SMT threads,
  packages and detected CCD/die information, with Intel hybrid P/E-core
  distinction preserved.
- **Live process tree** — hierarchical view with per-second CPU, memory, disk and
  network metrics.
- **Topology-aware affinity editor** — multi-processor-group systems get one mask
  per active group instead of a single 64-bit value.
- **Persistent rules** — exact / wildcard / path matching, strict
  (`SetProcessAffinityMask`) or soft (`SetProcessDefaultCpuSets`) scheduling, and
  optional CPU / I/O / memory priority pinning.
- **ProBalance** — foreground-contention detection that temporarily downgrades
  noisy background processes and restores them automatically, with live status,
  statistics and a JSONL journal.
- **Optional `CpumAffinityService`** — reapplies rules every five seconds, hosts
  the ProBalance runtime, and doubles as a privileged bridge so the un-elevated
  GUI never needs a UAC prompt to change a protected process.
- **Signed updates** — Tauri updater with minisign-signed artifacts and a
  `SHA256SUMS.txt` manifest on every release.

## Install

Download the installer for your architecture from the assets below:

| Architecture | Installer |
| ------------ | --------- |
| x64 | `CPU-Manager_v0.1.0_windows-x64-setup.exe` |
| ARM64 | `CPU-Manager_v0.1.0_windows-arm64-setup.exe` |

Also published in this release: the matching `.sig` signatures, the updater
archives (`.nsis.zip` + `.sig`), `latest.json`, and `SHA256SUMS.txt`.

The installer is a **per-user** NSIS package that installs into `%LOCALAPPDATA%`
and does not prompt for UAC. The app itself always runs un-elevated; only
installing or removing the Windows service asks for administrator rights, and
that is a single prompt for that action alone.

### Requirements

- Windows 10 or later (x64 or ARM64); WebView2 Runtime, which ships with current
  Windows installations.
- Windows 10 1803 or later for the **soft** rule mode (CPU Sets).
- Windows 11 24H2 or later for per-process **network I/O counters**; older
  versions report them as zero.
- Administrator rights **only** for service install / uninstall / start / stop.

### Verify your download

```powershell
Get-FileHash .\CPU-Manager_v0.1.0_windows-x64-setup.exe -Algorithm SHA256
```

Compare the hash with the matching line in `SHA256SUMS.txt`.

## Quick start

1. Start CPU Manager and let it load the CPU topology and the process list.
2. Open the **Process** tab to change one process's affinity and priorities right
   now, or switch to **Rules** to save a reusable rule.
3. Use **Apply Rules** to push every enabled rule onto the processes running now.
4. Use the **ProBalance** tab to set foreground contention thresholds and
   allowlists, and to watch the live status and journal.
5. Install the Windows service from the app if rules and ProBalance should also be
   enforced after sign-in and across reboots.

Rules and ProBalance configuration live in `%APPDATA%\com.open-nexa.cpum\`
(`affinity_rules.json`, `probalance.json`, journal and status files).

## Before you pin cores

Changing affinity affects both responsiveness and throughput. Test masks carefully
on hybrid CPUs and on machines running latency-sensitive workloads. ProBalance only
downgrades CPU and I/O priority — it never kills a process and never changes an
affinity mask. Priorities managed by a rule are excluded from ProBalance so the two
engines cannot undo each other.

## Known limitations

- Network I/O counters need Windows 11 24H2+ and read zero on older builds.
- Saving a rule does not apply it until you use **Apply Rules** or the service
  scans a matching process.
- PPL processes (and some anti-cheat / antivirus processes) cannot be modified at
  any privilege level; the error is surfaced as-is.
- A handful of success messages returned by the backend are not yet localized.
- ARM64 is built by CI from the same source; it has far less field mileage than x64.

## Upgrading from an early build

The bundle identifier moved to `com.open-nexa.cpum`, so the data directory moved
from `%APPDATA%\com.eason.cpum` to `%APPDATA%\com.open-nexa.cpum`.
`affinity_rules.json` is migrated automatically on first start. Installers built
before the identifier change **cannot be upgraded in place** — uninstall that
version first, then install v0.1.0.

## Security and reporting

The desktop app runs un-elevated; only service management elevates, and the GUI
reaches processes it cannot open through the service over a named pipe instead of
raising a UAC prompt. See
[SECURITY.md](https://github.com/open-nexa/cpum/blob/main/SECURITY.md) for the
privilege boundary and for how to report a vulnerability privately.
